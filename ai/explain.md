# Explain Error and Explain Test

Explain error and Explain test are dashboard features where Currents sends a test's recorded data to an AI model from an AI provider and shows you the answer. Currents makes the request to the model, so you do not need your own agent or API key.

* **Explain error** - for a failed test: the root cause, an error category, and up to three suggested fixes with code snippets
* **Explain test** - for any test: what the test does, what it checks, and what it depends on

The output is generated by an AI model. Review it before you act on it, the same as you would review a suggestion from a teammate.

{% hint style="info" %}
These features are off by default. They run only after Currents enables AI analysis for your organization and an organization admin grants AI usage consent. See [#enable-explain-error-and-explain-test](explain.md#enable-explain-error-and-explain-test "mention").
{% endhint %}

### Where to find them

Open a test in a run to open the test sidebar. The **Explain it** card has one row for each feature:

| Row               | When it shows                          |
| ----------------- | -------------------------------------- |
| **Explain test**  | Always                                 |
| **Explain error** | When an attempt of the test has failed |

Click a row to expand it. Currents sends the request when you first expand the row, not before. While the model works, the row shows "Analyzing the test…". If the request fails, the row shows the error and a **Retry** button.

Explain error analyzes the failed attempt. If a later attempt fails while the row is open, the row analyzes the new attempt.

### Explain error

Explain error analyzes one failed test attempt and returns:

* **Summary** - one line that states the root cause
* **Root cause** - a longer explanation of why the test failed
* **Category** - the type of failure, one of the [#ai-error-categories](explain.md#ai-error-categories "mention")
* **Suggested fixes** - up to three, ordered by confidence. Each fix has a description, a confidence level, and a code snippet when one applies. You can copy the snippet.
* **Related patterns** - short labels for common failure patterns that the error matches, when there are any

The model is instructed to identify the root cause, give concrete code changes instead of general advice, follow the practices of the test framework in the context (Playwright, Cypress, Jest, and others), and tell a flaky test apart from a real bug.

### Explain test

Explain test describes what a test does, for someone who has not read it. It does not debug a failure. It returns:

* **Summary** - what the test verifies
* **What it does** - the test's actions in order, in plain language
* **What it checks** - the assertions the test makes
* **Preconditions** - fixtures, hooks, or navigation the test depends on, when the model finds any
* **Notes** - caveats such as retries or flakiness, when there are any

The model is instructed to take everything from the recorded test data and not to add steps that the data does not show.

### AI error categories

Explain error puts each failure in one of nine categories:

* Network Error
* Element Interaction
* Assertion Failure
* Timeout
* Configuration Error
* Syntax Error
* Environment Error
* Flaky Test
* Other

The model picks the category from the test data. It can pick the wrong one.

Each suggested fix has a confidence level: **high**, **medium**, or **low**. The model assigns it and orders the fixes by it.

{% hint style="info" %}
The AI error category is not the same as the **Category** field in the [errors-explorer.md](../dashboard/test-suite-performance-explorer/errors-explorer.md "mention"). The Errors Explorer classifies every error by matching the error message against known patterns, without an AI model. The AI error category comes only from Explain error, for the test you asked about.
{% endhint %}

### Enable Explain error and Explain test

Two things must be true before the features run:

1. **Currents enables AI analysis for your organization.** Contact [support@currents.dev](mailto:support@currents.dev) to turn it on. Until then, the **Explain it** card does not show.
2. **An organization admin grants AI usage consent.**
   1. Go to **Organization settings**.
   2. Find **AI usage consent**.
   3. Turn it on.

Until an admin grants consent, the **Explain it** card shows a message instead of the rows. Admins see a link to organization settings. Other members see "Ask an organization admin to grant it in the organization settings."

The settings page shows who granted or revoked consent, when, and which version of the terms applied.

#### Revoke consent

An admin can turn **AI usage consent** off at any time. Currents asks for confirmation first. After you revoke consent, Explain error and Explain test stop working for everyone in the organization, and requests that are still in progress fail. Currents checks consent again right before it sends data to the model, so a request queued before you revoked consent is not sent.

### What data Currents sends to the model

For each request, Currents builds a text document from the recorded result of the test and sends it to the model. Explain error and Explain test use the same document. It contains:

* The spec file path, test title, status, attempt number, and duration
* The error message and stack trace, the error location (file, line, and column), and the code frame - the lines of test source around the error
* The steps before and after the failed step
* The full list of test steps
* Browser console messages and network requests around the time of the error, when a Playwright trace was recorded and analyzed
* Stdout and stderr
* The test framework and its version, the browser and its version, the operating system, and the project
* A one-line summary of how each other attempt of the test ended
* Links to the test's assets: traces, screenshots, videos, attachments, and the accessibility snapshot captured at the time of failure. Currents sends the links as text. It does not upload the files.

Currents does not send the Git repository, branch, pull request, or commit. It does not send the test's history from other runs.

If your tests print secrets to the console or to stdout, or capture them in step titles, that content is part of what Currents sends.
